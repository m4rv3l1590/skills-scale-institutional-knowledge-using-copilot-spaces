# Onboarding Checklist Template

This template provides a baseline checklist for onboarding any new team member to an OctoAcme project. Customize this checklist based on the specific role and project needs.

---

## Pre-Start Preparation (Manager/Team Lead)

- [ ] Confirm start date and schedule first-day activities
- [ ] Prepare workspace and equipment
- [ ] Request necessary system access and permissions
- [ ] Identify onboarding buddy/mentor
- [ ] Schedule welcome meeting with team
- [ ] Prepare project context document or briefing
- [ ] Add to communication channels and distribution lists

---

## Week 1: Foundation and Context

### Day 1: Welcome and Orientation
- [ ] Welcome meeting with manager and team
- [ ] Review role responsibilities and expectations
- [ ] Complete HR and administrative requirements
- [ ] Set up development environment and tools
- [ ] Receive access credentials and verify access
- [ ] Review organizational chart and key contacts
- [ ] Schedule regular 1:1s with manager

### Days 2-3: Project Context
- [ ] Read project charter and current roadmap
- [ ] Review **Project Management Overview** (`docs/octoacme-project-management-overview.md`)
- [ ] Review **Roles and Personas** document (`docs/octoacme-roles-and-personas.md`)
- [ ] Understand current project phase and upcoming milestones
- [ ] Review recent sprint retrospectives or lessons learned
- [ ] Familiarize with project communication channels (Slack, Teams, email lists)
- [ ] Attend team meetings as observer

### Days 4-5: Technical and Process Onboarding
- [ ] Review codebase/system architecture (if applicable)
- [ ] Understand version control workflow (branching, PR process)
- [ ] Review testing and quality assurance processes
- [ ] Understand deployment and release procedures
- [ ] Review documentation standards and where to find information
- [ ] Complete any required training or certifications
- [ ] Shadow experienced team member

---

## Week 2: Active Participation

- [ ] Meet 1:1 with key collaborators across roles
- [ ] Take on first small task or assignment
- [ ] Participate actively in team meetings and standups
- [ ] Ask questions and seek clarification proactively
- [ ] Review relevant project documentation in depth
- [ ] Begin to understand team dynamics and working norms
- [ ] Provide feedback on onboarding experience

---

## Week 3-4: Increased Responsibility

- [ ] Take ownership of assigned work items
- [ ] Contribute to team discussions and decision-making
- [ ] Understand escalation paths and when to use them
- [ ] Build relationships with stakeholders
- [ ] Identify areas where you can add value
- [ ] Share initial observations or improvement ideas
- [ ] Update personal learning goals with manager

---

## 30-Day Check-in

- [ ] Review accomplishments and progress with manager
- [ ] Discuss any challenges or blockers
- [ ] Clarify expectations and success criteria
- [ ] Adjust onboarding plan if needed
- [ ] Identify additional resources or support needed
- [ ] Set goals for next 30-60 days

---

## 60-Day Check-in

- [ ] Assess integration into team and project
- [ ] Review performance against initial goals
- [ ] Discuss long-term career development
- [ ] Identify opportunities for increased responsibility
- [ ] Provide feedback on onboarding process for future improvements

---

## 90-Day Check-in

- [ ] Evaluate full ramp-up and productivity
- [ ] Confirm understanding of role and expectations
- [ ] Discuss performance and any areas for development
- [ ] Set goals for next quarter
- [ ] Celebrate successes and contributions
- [ ] Transition from onboarding to regular performance management

---

## Role-Specific Additions

**For technical roles (Developers, DevOps, Security):**
- [ ] Complete security training and acknowledge security policies
- [ ] Understand incident response procedures
- [ ] Review technical standards and coding guidelines
- [ ] Set up local development environment
- [ ] Make first code contribution (starter issue/bug)

**For customer-facing roles (Support, Customer Success):**
- [ ] Complete product training
- [ ] Review customer communication guidelines
- [ ] Shadow customer interactions
- [ ] Learn support tools and ticketing systems
- [ ] Review SLAs and support metrics

**For design/content roles (UX/UI, Documentation):**
- [ ] Review brand and style guidelines
- [ ] Understand design/documentation review process
- [ ] Access design/content management tools
- [ ] Review accessibility and usability standards
- [ ] Meet with user research team (if applicable)

**For management/leadership roles (Product Manager, Project Manager):**
- [ ] Understand stakeholder landscape and needs
- [ ] Review decision-making frameworks
- [ ] Meet with executive sponsors
- [ ] Understand budget and resource constraints
- [ ] Review strategic goals and OKRs

---

## Tips for Success

- **Ask questions early and often** - it's expected during onboarding
- **Take notes** - there's a lot of information to absorb
- **Build relationships** - connections are as important as knowledge
- **Be patient with yourself** - ramp-up takes time
- **Seek feedback** - ask how you're doing and what to improve
- **Share your perspective** - fresh eyes can spot improvement opportunities
- **Update documentation** - if something wasn't clear, help improve it
